# Server (Go)

New to Go? Read the code in this order:

1. `cmd/api/main.go` — the program starts here. Loads config, connects to Postgres, builds the router, runs the server and shuts down gracefully on Ctrl+C.
2. `internal/app/router.go` — **dependency injection by hand**: each module gets `NewRepository -> NewService -> NewHandler`, then its routes are mounted.
3. `internal/modules/users` — the smallest complete module. Then `devices`, `vault`, `sync`, `auth`.
4. `internal/db` — generated by sqlc from `queries/*.sql`. Change the SQL, then run `pnpm db:generate`.

| Go idea                                     | Where to see it                                          |
| ------------------------------------------- | -------------------------------------------------------- |
| Interfaces as "ports"                       | `Repository` in every module                             |
| Errors are values (`if err != nil`)         | everywhere; `errors.Is(err, pgx.ErrNoRows)` in handlers  |
| `context.Context` for cancellation/timeouts | first arg of every service/repo method                   |
| Struct tags for JSON                        | `model.go` files (`json:"displayName"`)                  |
| Goroutines + channels                       | `internal/platform/httpserver`                           |
| Table-free unit tests                       | `pkg/token/token_test.go`, `internal/app/router_test.go` |

Commands (from repo root or here):

```bash
pnpm server          # hot reload with air
go test ./...        # tests
go vet ./...         # static checks
pnpm db:migrate      # apply migrations
pnpm db:generate     # sqlc (brew install sqlc)
```

Stubbed endpoints return **501 Not Implemented** (OAuth callback/id_token exchange, passkey ceremonies, sync push).
Their TODO comments describe the steps.
